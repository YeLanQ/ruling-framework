# 00 · 概览：为谁做，做什么

## 1. 定位

Ruling Framework 是一个**通用裁定权大模型框架**。它假设模型能力会持续变化、供应商会更换、弱模型会长期存在，因此不把系统可靠性押在模型能力上，而是押在一组确定性结构上：

- 模型只能**提议**；
- 系统决定**能不能执行**；
- 唯一执行通道负责**真正执行**；
- 机器门禁负责**验证**；
- 用户保留**放行权**。

这套结构不依赖训练。模型可以是任何 OpenAI 兼容端点，也可以是本地 Ollama / LM Studio；知识以文件、图谱、索引注入，修正一次知识不需要重训。

## 2. 三类目标用户

### 2.1 OPC（一人公司）

一个人承担创意、决策、交付，AI 作为“员工”承担生产。最需要的是：

- 写操作不能悄悄发生；
- 对外发布、付款、删除必须由人完成；
- 每次交付有可导出的过程记录；
- 知识沉淀为标准作业程序，而不是留在聊天记录里。

`opc` 包把读操作设为绿灯、写操作设为黄灯、对外不可逆动作设为红灯。审批为 owner 单角色、任务绑定、10 分钟过期。

### 2.2 小公司

多人协作，能力与审批需要按角色分层。最需要的是：

- 谁能调什么，由源头能力组决定；
- 发布等敏感动作需要多角色批准；
- 权限变更本身不能由 Agent 自主执行；
- 每个动作可追溯到执行者角色。

`smb` 包提供 `owner / editor / reviewer / viewer` 四个角色；发布准备需要 `reviewer + owner` 双角色批准；`role.grant` 是红灯。

### 2.3 工业设计（产品/结构设计）

设计对象有版本、参数、BOM、附件与安全/合规约束。最需要的是：

- 普通参数可辅助修改，安全关键参数绝对不能由 Agent 改；
- CAD 交换格式不能走通用文本写入；
- 每次变更留下 before/after 哈希与修订号；
- 发布与安全签核保留给人。

`industrial-design` 包提供动态红灯（安全参数）、格式锁（STEP/STL/3MF/PDF/CSV）、revision 与 provenance。

## 3. 它是什么 / 不是什么

**是**：

- 一个可嵌入的 TypeScript/Node 库（`@ruling` 单包，子路径导出）；
- 一个本地优先 CLI；
- 一个 MCP stdio 服务；
- 一个只绑定回环的 HTTP 服务；
- 三个可直接运行的行业参考包。

**不是**：

- 不是训练框架，不提供 SFT/LoRA/fine-tune；
- 不是模型网关或提示词市场；
- 不是 CAD/PLM/ERP 产品；
- 不是多租户 SaaS；
- 不是操作系统沙箱；
- 不是 UI 产品。

## 4. 一次请求发生什么

```text
用户任务
  → 大脑前置：分段、知识路由、候选动作、可能的绿色直执行
  → 模型提议：调用哪个动作、传什么参数（或正文 JSON 兜底）
  → RulingEngine：
      能力面登记？→ 源头授权？→ 区域解析 → gate()
      → 数据边界 → 输入 schema → 唯一执行器
  → 观测：台账 + 因果链 + 审计哈希链
  → 回执：ok / needConfirm / denied / error
```

`needConfirm` 是一个**后端状态**，不是模型措辞。模型不能把它解释成“已批准”，也没有任何工具可以调用批准。

## 5. 为什么不做训练

训练解决的是“模型能不能想出正确动作”，但生产事故更常见的是：

- 想出了动作，却在错误的对象上执行；
- 执行了，但没有留下可归因的记录；
- 上一个任务得到的批准，被这个任务继承；
- 能力表里没有的动作，被模型“发明”出来并执行。

这些都不是模型能力问题，而是裁定权配置问题。把验证、执行、放行从模型侧移走，比收集数据再训练更直接、更可测试，也更容易跨模型供应商迁移。

## 6. 采用路径

1. **只读体验**：`pnpm demo` / `pnpm demo:industrial`。
2. **接自己的工具**：实现 `ActionExecutor`，在 pack manifest 里登记动作与区域。
3. **接真实模型**：设置 `RULING_BASE_URL / RULING_MODEL / RULING_API_KEY`，或使用任意 OpenAI 兼容端点。
4. **接现有系统**：用 `RulingEngine` 作为库，把现有命令注册表映射为动作表。
5. **接外部 Agent**：MCP（stdio）或 HTTP（回环）。
6. **做行业变体**：复制一个 pack，改动作、区域、角色、格式锁、知识种子。

## 7. 与其他路线的关系

- **RAG / 知识图谱**：本框架保留检索，但取消检索的裁决权。向量只提名候选，进入哪个决策单元由前置路由决定。
- **Guardrails**：护栏如果只在对话流里，模型可以绕过；本框架把约束放在执行通道与权限生命周期里。
- **微调 / SFT**：把知识写入参数，任一事实修正都需要再训练；本框架的知识按层更新，成本随层递减。
- **全能式 Agent**：以任务完成率为唯一目标；本框架采用伴随式定位，以过程可控性为先决条件。

# 08 · 局限与诚实的能力声明

本框架的目标是“把裁定权放对位置”，不是“让 Agent 绝对安全”。以下是明确边界。

## 1. 威胁模型

### 1.1 防什么

| 威胁 | 防线 |
| --- | --- |
| 模型判断错误 | 三区门控、参数 schema、格式锁、红灯 |
| 提示词注入 | 执行权在本地内核；能力面封闭；黄灯批准；模型输出视为不可信输入 |
| 弱模型空转 | 轮次上限、空回复救援、假完成守卫、同参失败短路 |
| 外部客户端滥用 | 回环绑定、角色能力组、数据边界、审计 |
| 路径穿越 | 拒绝 `..`、反斜杠、绝对路径；词法越界检查 |
| 格式损坏 | 格式锁 + 专用通道 |
| 不可审计 | 统一审计、哈希链、决策计数 |
| 跨任务越权 | 审批按任务文本绑定、TTL、纯内存 |

### 1.2 不防什么

- **同机同用户不是沙箱**：有文件系统权限的进程可以绕过应用内所有门。
- **不防恶意宿主**：宿主应用可以直接调用执行器或改状态文件。
- **不防模型输出内容错误**：框架限制“能执行什么”，不保证“模型说的内容真实”。
- **不防供应链攻击**：运行时零依赖降低了面，但 Node 与开发依赖仍属信任基。

## 2. 安全边界

- **token 不是鉴权**：HTTP 的 `x-ruling-token` 只是本地脚本便利；不要端口转发。
- **角色不是身份认证**：CLI/MCP/HTTP 的角色由调用方断言；没有登录、会话、签名。
- **无多租户**：单工作区、单进程模型；没有租户隔离。
- **无远程监听**：HTTP 只绑定 `127.0.0.1`；没有 TLS。
- **符号链接未解析**：`resolveSafe` 是词法检查，不调用 `realpath`；工作区内若有指向外部的符号链接，可能绕出根目录。不要在工作区放置不可信符号链接。
- **无跨进程文件锁**：并发进程写同一工作区是最后写入者获胜。
- **无通用撤销**：框架记录审计与变更哈希，但不提供跨动作回滚。需要撤销时由执行器自己实现。
- **协议不承诺幂等**：重试可能重复执行（例如重复邀请）。调用方应按任务/业务状态去重。

## 3. 功能边界

- **单 Agent**：没有多 Agent 协作、任务分派、跨 Agent 授权协调。
- **MCP 最小子集**：只实现 `initialize / tools/list / tools/call / ping`；没有 resources、prompts、sampling、elicitation。
- **HTTP 本地**：没有鉴权、限流、CORS、TLS、多用户。
- **无 UI**：确认界面由宿主实现；CLI 只有 y/N。
- **无真实 CAD/PLM/ERP**：工业设计包是 JSON 参考实现；真实系统需要替换 executor。
- **发布/签核只在框架内阻断**：框架没有实现外部的发布系统或签核流程，只保证 Agent 不能在此执行。
- **无大文件索引**：没有 `file.index/search/module`；大文件读取受 2MB 上限。
- **无流式输出**：Provider 是非流式 `/chat/completions`；思考/reasoning 字段不解析。
- **无工具并行**：同一轮的多个 tool call 顺序执行。
- **JSON Schema 子集**：不支持 union、oneOf、pattern、format 等；复杂结构需执行器自行校验。

## 4. 知识与模型

- **语义天花板**：128 维字符 n-gram 哈希嵌入刻画字符重叠，不理解同义改写与跨语言。
- **冷启动**：因果链为空时路由主要依赖关键词与种子；新领域初期效果有限。
- **换域成本**：种子库、关键词、动作表都是领域定制的；跨行业需要重新设计 pack。
- **无受控基线**：没有在固定任务集上对比“有/无门控”“有/无知识层”的成功率、介入次数、token 成本。
- **效能比未校准**：0.99、先验 40@0.995、速度预算都是参考值，不是跨行业最优值。
- **模型质量仍重要**：弱模型可能反复调用错误动作；框架会让它失败得可控，但不会让它变聪明。
- **外部知识仍是字符检索**：JSON/JSONL/Markdown/HTTP 只是载入通道，不引入语义模型；同义改写仍可能命中不到。
- **外部源解析是简化的**：Markdown 只取一级标题与首个段落作摘要；JSONL 坏行直接跳过；JSON 只接受数组或 `{units:[]}`。
- **外部源不持久化**：每次启动重新加载；外部系统不可用时，该源本轮缺失，不会回退到上次缓存。
- **失败教训是标记 + 文本**：自动生成的 `failure:<action>` 记录原因与错误码，但不会自动验证“下次是否真的避免”；需要人工或外部评测闭环。
- **语义不等于理解**：别名、同义词、领域与状态权重是确定性的词面/元数据增强，不做同义改写理解或跨语言语义对齐。
- **冲突检测是显式的**：`knowledge conflicts` 只报告 `contradicts` 声明，不自动推断两条知识在语义上矛盾。
- **去重阈值是启发式**：`dedupe` 用余弦与共享别名，0.95 是默认值；不同领域可能需要调整，且不会自动合并，只给候选。
- **前置归一化依赖模型输出格式**：NormSpec 需要模型只返回 JSON；坏格式/超时/空描述会回落规则链路，但该次归一化收益为零。
- **任务分层是规则启发式**：问句、模糊词、候选分差都是确定性规则，不理解深层语义；`fuzzy`/`suggest` 可能误判，需要用户补充或宿主调整关键词。
- **澄清只重规划一次**：`onClarify` 返回补充后不会无限追问；仍模糊就返回 `needs-clarification`。

## 5. 审计与隐私

- 审计记录包含任务文本前 80 字、完整任务（截断 200 字）与文件路径；可能含敏感信息。
- `.ruling/knowledge/experience.jsonl` 与 `.ruling/knowledge/errors.jsonl` 可能保存任务文本与失败原因。
- 审计、知识与状态文件**未加密**。
- 哈希链只能证明“文件在某个点之后被改动”，不是法律认证；持有文件系统权限的人可以整体替换文件与链。
- 审计环形缓冲只保留最近 50 条；完整历史在 `audit.jsonl`。
- HTTP 外部知识源由本地配置指定；不要把不可信来源配置为自动加载，也不要在其中放置密钥。

## 6. 行业边界

- **红灯清单是策略，不是穷举**：每个行业需要自己定义“不可逆/不可自主”的动作。
- **工业安全参数集合是示例**：`wallThickness / safetyFactor / materialGrade / loadRating` 只是参考，真实规则应来自 PLM/法规。
- **DFM 只是建议**：`dfm.check` 不构成发布授权。
- **OPC 的发布/付款/删除是示例红灯**：真实业务可能有更多不可逆动作。
- **小公司角色模型简化**：没有组织架构、代理、委托、双人复核之外的复杂审批链。

## 7. 工程约束

- 单进程、单工作区；没有分布式执行。
- 本地文件系统；没有数据库、消息队列、对象存储。
- Node 20+；没有浏览器运行时。
- 没有遥测；没有远程日志。
- 没有自动提交、没有 CI 配置；验证靠 `pnpm verify`。

## 9. 如何诚实使用

- 把框架当成“执行边界与审计层”，不是“安全沙箱”。
- 对不可逆动作保留人工确认；不要把红灯改成黄灯来追求自动化率。
- 在高风险行业，先做小范围试点，保留人工复核。
- 不要对外宣称“零事故”“绝对安全”“完全自主”；本框架没有这样的证据。
- 对模型输出保持不信任：它只是提议，执行前仍要过门控、边界与 schema。
